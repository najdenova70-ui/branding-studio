# Branding Studio

Узкий инструмент ребрендинга фиксированных экранов мобильного приложения.

## Продуктовый контракт

Пользователь может:

- заменить четыре подготовленных бренд-ассета;
- изменить только цветовые стили, подключённые к текущим экранам;
- проверить результат в фиксированной презентации и интерактивном прототипе;
- сбросить отдельный ассет, цвет или все цвета к значениям Figma.

Пользователь не может:

- менять тексты, размеры, расположение и состав элементов;
- создавать, удалять или перестраивать экраны и слайды;
- менять навигационный граф и псевдофункциональность;
- импортировать `.fig` или произвольные экраны из интерфейса.

Новые экраны добавляются разработчиком по согласованному макету Figma: экран
реализуется как фиксированный React-компонент, регистрируется в `ScreenRegistry`,
подключается к `NavigationGraph` и при необходимости к `SlideRegistry`. После
этого наружу выводятся только подтверждённые бренд-слоты и токены.

## Ассеты

| Слот | Формат | Пропорция/минимальный размер | Где используется |
| --- | --- | --- | --- |
| App Icon | PNG | 60×60 или больше, 1:1 | плитка и обложка презентации |
| Splash Background | PNG | 375×812 или пропорциональный 2×/4× | заставка авторизации |
| Logo | SVG | вектор, без ручной подгонки | заставка авторизации |
| Navigation Menu Background | PNG | 304×175 или пропорциональный 2×/4× | шапка бокового меню |

Studio проверяет формат, пропорцию и минимальное разрешение. Режим вписывания
зафиксирован макетом; пользователь его не настраивает.

## Запуск

Локально:

```bash
npm install
npm run dev
```

Production Docker:

```bash
copy .env.example .env
docker compose up -d --build --remove-orphans
```

Интерфейс: `http://127.0.0.1:8088`.
Healthcheck: `http://127.0.0.1:8088/healthz`.

## Рабочие режимы

- **Веб-версия** — зарезервированный пустой раздел.
- **Мобильная версия** — интерактивный фиксированный сценарий. Миниатюры экранов появляются у нижнего края при наведении.
- **Презентация** — неизменяемый просмотр утверждённых слайдов.
- **Экспорт** — PDF, PPTX и публичная read-only ссылка.

Правая панель показывается только в мобильном режиме редактора. Она содержит бренд-ассеты и цвета, которые реально используются текущим экраном; обе группы сворачиваются. Тексты, геометрия, навигационный граф и состав экранов через интерфейс не меняются.

## Публичная демонстрация

Кнопка «Создать ссылку» сохраняет автономный снимок бренда, включая изображения, в `share-api`. Ссылка `/share/<id>` разрешает только мобильный просмотр, презентацию и экспорт. Редактирование и повторный шаринг в ней отключены.

Снимки по умолчанию живут 30 дней и хранятся в Docker volume `share-data`, поэтому переживают перезапуск контейнера. Настройки:

- `SHARE_TTL_DAYS` — срок жизни ссылки, 1–365 дней;
- `SHARE_MAX_RECORDS` — предельное число снимков, старые вытесняются;
- `ALLOWED_ORIGINS` — необязательный список разрешённых origin через запятую.

Для отдельного демонстрационного поддомена достаточно направить его на контейнер `web`: SPA-маршрут и API уже работают через один origin.

Проверка реального экспорта через установленный Microsoft Edge:

```bash
npm run test:export
```

## Архитектура

- `BrandConfig` — единственный источник бренд-ассетов и цветов.
- `BrandContext` — единственная точка изменения бренда.
- `ScreenRegistry` — фиксированный список экранов.
- `NavigationGraph` — фиксированные переходы прототипа.
- `SlideRegistry` — фиксированная презентация.
- `ScreenRenderer` — общий рендер экранов для презентации и прототипа.

Стек: React 18, TypeScript strict, Vite 8. Production — Nginx-контейнер и компактный Node.js API шаринга.
